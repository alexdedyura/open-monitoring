## Requirements

- Windows 10/11, 64-bit.
- Administrator rights — the app requests elevation at launch (SMART counters
  and ETW frame capture need it, same as MSI Afterburner).
- The [PawnIO](https://pawnio.eu) kernel driver for CPU temperature and power —
  the app offers a one-click install on first launch, see below.

## Download

Versioned releases are the supported downloads and are used by the in-app
updater. Every push to the default branch is also built by GitHub Actions and
published to the rolling
[**latest** prerelease](https://github.com/alexdedyura/open-monitoring/releases/tag/latest)
for testing.

Grab the installer or `open-monitoring.exe` from the
[newest versioned release](https://github.com/alexdedyura/open-monitoring/releases/latest).
The portable executable is **one file with no prerequisites**. The
native helpers (the sensor engine and PresentMon) are compiled into the
executable and unpacked automatically on first use into a hidden
`.open-monitoring\bin\` folder **next to the executable**.

## First launch

1. Run `open-monitoring.exe`. Windows shows a UAC prompt — the app needs
   administrator rights for SMART data and frame capture.
2. If the PawnIO driver is not installed yet, the app shows an **install
   gate** and stays locked until the driver is present. Click install — the
   gate runs the official winget package:

   ```
   winget install --id namazso.PawnIO --exact --silent
   ```

   Where winget is unavailable, the official download page is opened instead;
   the app never downloads or executes an installer of its own.
3. Once the driver reports in, the dashboard opens by itself — no restart
   needed.

The installer places the app below the current user's LocalAppData directory,
so normal launches do not require elevation. Windows may show one UAC prompt
while the optional PawnIO component is installed.

When upgrading a machine-wide v0.6.0 installation, run the new installer
before removing the old version. It copies `config.json`, `sessions.db` and its
WAL files into the new per-user data directory; generated helpers and WebView2
caches are rebuilt instead of migrated.

The sensor engine takes a few seconds to start reporting, so GPU details may
appear shortly after the dashboard does.

## Updating

The **About** tab checks GitHub for a newer release and updates the app in
place with one click — settings and recordings are untouched. It also checks
once a day on its own, which can be turned off in Settings.

To update by hand, download the new `open-monitoring.exe` from the
[newest versioned release](https://github.com/alexdedyura/open-monitoring/releases/latest)
and replace the old file. Everything the app writes lives in the hidden
`.open-monitoring\` folder beside it, so it survives the swap — and moving that
folder together with the executable moves the whole installation.
